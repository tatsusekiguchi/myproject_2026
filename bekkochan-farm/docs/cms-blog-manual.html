CMSブログ機能
実装・移行マニュアル

独自タグ、コンポーネント設定、BEKKOのdata-block生成を1つの資料に。提供された3つのHTMLをもとに、オフラインで参照・生成できます。

1. CMSブログの構成

CMSは、登録された記事をデザインコンポーネントの独自タグに差し込みます。記事データ、表示件数・並び順などのブロック設定、表示用HTMLをそれぞれ管理します。制作時のダミー記事はCMS登録用HTMLでは1件の繰り返し元に置き換えます。

要素役割
webgene-blogCMSコンポーネント全体の囲み
webgene-header繰り返さない見出し
webgene-item記事1件の繰り返し元。表示件数はCMS設定で指定
webgene-item-content本案件の詳細本文の囲み。既存のpostBoxと併用
webgene-paginationCMSで生成する一覧のページ送り。ダミーのliは登録しない

資料のコーディング例はsection.webgene-blogとarticle.webgene-itemを使用し、sectionの囲みを必須と説明しています。一方、提供data-blockはsectionとdiv.webgene-itemです。本案件の構造タグ方針はdivです。生成時はdivをデフォルトとし、CMS側の要件確認後にsectionを選べます。クラスだけで認識されるか、divのitemが繰り返されるかはCMS実機で確認してください。

2. 使用する独自タグ

独自タグ内容・使い方
%itemTitle%記事タイトル
%itemContent%記事本文
%itemCategory%カテゴリ名
%itemDate.format(Y-m-d)%記事の日付。例：2026-10-05。PHP date形式
%itemRecordDate.format(Y-m-d H:i:s)%
%itemUpdateDate.format(Y-m-d H:i:s)%		登録日時・更新日時
%itemImageL(0)%先頭画像の大サイズ。画像タグを直接差し込む位置に使用
%itemImageSrc%画像URL。画像タグを返す独自タグとは区別する
%itemLink.to(blog)%記事詳細ページへのリンク。blogは詳細ページのパス
%item.pdf%PDFのリンク先。現行PugにPDF欄がないため標準生成には含めない
%groupName1% / %groupName2%カテゴリ設定のグルーピング順に対応。カテゴリ番号／カテゴリ名

画像サイズと番号

資料ではS＝横幅600px、M＝800px、L＝1000px、指定なし＝オリジナル。規定幅未満の画像は拡大されます。番号は0が1枚目、1が2枚目です。トピックスの番号は0〜9、事例集は0〜14と記載されています。

元資料の「2枚目の画像を大きいサイズ」の例は、コードがM(1)になっています。サイズの凡例に合わせるならL(1)です。ブログの番号付きタグは提供data-blockのL(0)を採用しています。Instagramの%item.canonical%はdata-blockだけに登場するため、対応データソースでの置換確認が必要です。

トピックス・事例集の追加タグ

%item.comment.nl2br% は説明文、%item.movie.html_entity_decode% はYouTube、%itemImage2M(0)% は事例集のみの追加画像です。ブログと同じ項目がすべて使えるとは限りません。

3. 管理画面の設定

以下は資料の例と本案件の表示数を合わせた登録参考値です。設定JSONはCMSの自動インポート形式ではありません。

用途設定参考値
ブログ一覧テーブルblog／行数10（資料例）／date・降順／ページング有／ページ番号5
TOPブログテーブルblog／行数3（本案件）／date・降順／ページング無。資料例の行数は5
カテゴリテーブルblog／行数100／category_sort・昇順／ページング無／グルーピング：blog_category_cd, category_name, category_sort
記事詳細詳細用デザインコンポーネントを登録し、詳細ページへ配置。記事リンク先を対応させる
InstagramCMS側でInstagram用データソースとアカウント連携を設定。取得処理をフロントに追加しない

カテゴリリンクとブロックID

/bloglist?wg[wgc-実際の一覧ID_cate]=%groupName1%

リンクにはブログ一覧データブロックのIDを使います。カテゴリ自身のIDではありません。提供ファイルの固定IDはサンプルとして扱い、移行先のIDに置き換えます。カテゴリ抽出には対象のブログ一覧ブロックが必要です。

抽出・並び替え

カテゴリ抽出はblog_category_cdなどを完全一致で指定します。title・contentなどは完全一致または部分一致。複数のソート条件は例としてdate desc, sortがあり、その場合は別の「順番」設定が無視されると資料に記載されています。資料のcd descと「登録が古い順」という説明には差があるため、移行先で実際の並びを確認してください。

アーカイブ・件数・詳細の前後リンク

月別アーカイブはグルーピングdate、拡張YM（日本語はYM-JA）。リンクは/bloglist?wg[wgc-一覧ID_ym]=date|%groupName1%です。標準の5ブロックには含めません。

件数表示：%pageItems%、%totalItems%、%pageFirstItem%、%pageLastItem%、%page%、%totalPages%。詳細の前後リンクは%prevPageLink.to("前の記事へ","前の記事はありません")%と%nextPageLink.to("次の記事へ","次の記事はありません")%。並び順はCMSのソート設定に従います。

4. 移行用data-blockを生成

一覧ブロックIDと移行先のページパスを入力すると、カテゴリ・詳細・一覧・TOPブログ・Instagramの5種類を生成します。保存したHTMLから用途ごとにコピーしてCMSへ登録します。CMSへの自動登録や記事データの移送は行いません。

一覧ブロックIDを入力してください。

5. CMS移行の手順

  1. 移行先のブログ一覧・詳細ページのパスを決める。
  2. CMS管理画面でブログ一覧データブロックを作成し、一覧IDを取得する。
  3. 上のツールへIDとパスを入力し、ルートタグの要件を確認して生成する。
  4. 各HTMLを別々のデザインコンポーネントとして登録する。まとめファイルをサイト本文へ一括挿入しない。
  5. 管理画面で記事テーブル・表示件数・ソート・ページング・グルーピングを設定し、該当ページの表示位置へ配置する。
  6. カテゴリと一覧IDの紐づけ、記事の詳細リンク、画像・日付・タイトル・本文、ページ送り、0件表示、Instagram、PC/SP表示を確認する。

このHTMLは単体で使えます。外部通信・追加ライブラリは不要です。現在のPug/Sassや生成済みサイトHTML/CSSは書き換えません。ブロックのクラスは本案件の既存構造に合わせています。サイトの構造変更時はテンプレートを更新してください。

コマンドでの生成

同じ設定を繰り返し使う場合は「CLI用設定JSONを保存」で取得したmigration.jsonをcms/へ置き、次のコマンドを手動実行します。

python3 scripts/create_data_block.py --config cms/migration.json

cms/generated/へ5つの個別HTML、data-block.html、cms-settings.jsonを出力します。既存出力の上書きには--overwriteが必要です。生成用の編集元はcms/blog-blocks.jsonです。変更後はpython3 scripts/sync_cms_manual.pyを手動実行し、ブラウザー版の埋め込みテンプレートを同期してください。

詳細ページのページャーについて

<span class="webgene-item-aroundPageLink webgene-item-prevPageLink">%prevPageLink.to("前の記事へ","前の記事はありません")%</span>    <span class="webgene-item-aroundPageLink webgene-item-nextPageLink">%nextPageLink.to("次の記事へ","次の記事はありません")%</span>

上記のソースarticleタグの内側に入れることで詳細ページにページャ―を表示することができます。
次のページ及び前のページの判定は一覧ページの「ソート項目」「順番」が反映されます。
例えば、ソート項目が「date」、順番が「降順」の場合に「次の記事へ」をクリックすると、今表示されている記事の日付より古い日付の記事が表示されます。

解説

トピックスはブログ、新着情報と比べ使用できる独自タグの種類が増えています。
独自タグの説明については ブログの作り方（独自タグ編） をご参照ください。

トピックス、事例集で画像が登録されていない場合にimgタグの親要素を削除するjs例

上記の詳細ページコーディング例では、画像が登録されていない箇所は空のdivが残ってしまいますが、その空のdivを削除するjsです。
HTMLは上記の詳細ページコーディング例の場合を想定しています。

                                        $(".imgBx").each( function() {
                                            if( !($(this).has('img')).length ){
                                                this.remove();
                                            }
                                        });

記事データブロックのコンポーネント設定例

記事詳細ブロックのコンポーネントは作成したテンプレート（各自で登録したデザインコンポネント）を選びます。


アーカイブのコーディング例（共通）

デザインコンポネント の名称は仮に「archive」にします。 

                                        <section class="webgene-blog">
                                            <article class="webgene-item">
                                                <a href="/一覧ページのパス?wg[wgc-■■■_ym]=date|%groupName1%">%groupName1%</a>
                                            </article>
                                        </section>
解説

wgc-■■■_ym の箇所は記事データブロックのIDと紐づける必要があります。
そのため、アーカイブを表示する場合はブログ一覧を必ず表示しなければなりません。

アーカイブでのコンポーネント設定例（共通）

項目 設定例
テーブル blog（ブログの場合）
news（新着情報の場合）
topics（トピックスの場合）
cases（事例集の場合）
1ページ当たりの行数 1000
ソート項目 1
順番 降順
テンプレート archive(自分で決めたテンプレート名)
ページング 無
グルーピング date
グルーピング拡張 YM

グルーピング拡張「YM」は「YM-JA」にすることで日本語での月表示が可能です。
